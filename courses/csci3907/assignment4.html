Part I: Counting FLOPS

In slide #14 in the Jagode/Danalis lecture we covered, there's a nice example of using PAPI to count not just the total compute cycles we got with our in-class PAPI intro, but also the number of FLOPS (Floating-Point Operations Per Second), a crucial benchmark for intensive numerical computations like modern AI / Deep-Learning. In this exercise we will combine both programs to get the FLOPS count. Crucially, we will need to check the result of each PAPI call, as we did in hello-world, to ensure that we don't silently continue to the next step if something doesn't work. To do this, I first wrote a little Check() function that ensures that the result of the PAPI operation equals PAPI_OK. If it isn't, I report the error and exit the program immediately by calling exit(1); (which requires #include at the top).

Part II: Creating a helper utility

Looking over the PAPI examples you can find online, you'll see a common pattern:

  1. Call PAPI_library_init() to start PAPI and check that you have the current version.
  2. Call PAPI_create_eventset() and check the result
  3. Call PAPI_add_events() and check the result
  4. Call PAPI_start() and check the result
  5. Run the code you want to profile
  6. Call PAPI_stop() to get the event counts
Since copy-pasting these steps over and over for each new PAPI application is a clear violation of the DRY Principle, let's write a little utility class that we can reuse to get the counts for a particular event type. Specifically, in a file papi_util.hpp create a PapiUtil class with two public methods, void StartCountingFlops() long long GetCount(), and a private method Check() to do the result-checking at each step. Once you've done that, the code in the main() of your FLOPS-counting program part2.cpp will be very simple: 
    auto papi = PapiUtil();

    papi.StartCountingFlops();

    // Put your floating-point calculations loop here

    printf("FLOPS=%lld\n", papi.GetCount());

Part III: Counting cache misses

As we discussed in class, the reason that the struct-of-arrays approach runs so much faster than array-of-structs approach is that putting data of a common size (int, short, char) in a contiguous block of memory increases the likelihood that the data we want will already be in the cache (ideally, the Level-1 cache L1) when we try to access it. In other words, we'd like to minimize the number of cache misses caused by our code.

So, for this exercise, you're going to augument your PapiUtil class by adding a method StartCountingL1Misses(). As usual, copy-paste-modify (from StartCountingFlops(), followed by a little code-factoring, should make it easy to to implement this new method.
